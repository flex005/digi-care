Measurements — build to these exactly

Consent tab — two axes, two columns

All eight types always listed, iterated from the constant. Row minmax(0,1fr) 13rem 17rem auto, gap 20px, padding 15px 24px. Type name 14.5px/600 with a plain-English line beneath at 12px ink-500 saying what consenting to it actually permits — a consent nobody can explain is not informed. Outcome and authority are separate columns because they answer different questions. What was decided: not sought (hatched) · pending (info) · given (positive) · refused (plain, on bg-surface-sunken) · withdrawn (caution). Who decided it: the resident, a best-interests process, or a health-and-welfare LPA holder — with the capacity assessment that authorised it named beneath at 11.5px. Refused is not a failure treatment. A resident refusing is them exercising a right, and caution or critical would make the record disapprove of them. Not sought and pending carry no authority — nothing has been decided, so there is nobody who decided it, and the column renders the hatched "nobody has decided" rather than a blank. A withdrawn consent whose effects have not been undone carries the hatched remains block beneath its row, naming each thing that still exists and how many.

The capacity gate

It is a gate, not a field: the question stands alone at 18px/700 before any consent detail exists, and nothing else is reachable until it is answered. No default selection. Save disabled while unanswered, the outstanding item named in the footer, the unanswered state rendered as the hatch — same shape as the risk instrument's no-default rule. Choosing "lacks capacity" reveals both MCA stages, both required. A conclusion with no impairment recorded and no functional finding is not an assessment, and neither field can be empty. The scope selector names the decisions this assessment covers. One assessment may name several decisions; it may never be general. A consent can only reference an assessment that names its own type, so "has capacity" applied to a decision nobody assessed against is not expressible. Where the resident has no health-and-welfare LPA on record, that authority is not offered and the screen says why rather than presenting it and failing on submit.

Withdrawal — the block is the screen

Downstream effects are data, not prose. A sentence cannot be asserted against, so a withdrawal that forgot to mention the photographs would look identical to one that did — the product's own failure inside the dialog written to prevent it. Each effect renders as its own row with its count, and a test asserts the dialog names every one. Block 18px 22px, 5px left border, hatched. Heading 15px/800 stating what withdrawing does not undo. Each effect a white card inside at 11px 14px, name 13.5px/700, explanation 12px ink-500, count right-aligned at 12px/800. An effect whose count is unknown renders "not counted" in the unrecorded treatment rather than zero — nobody knowing how many is not the same as none. Cross-module effects belong here too: withdrawing photography while Family Portal Access still stands is a real consequence and is checkable from data.
